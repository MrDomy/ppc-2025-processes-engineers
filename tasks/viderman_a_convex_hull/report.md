## 1. Введение

В компьютерной графике и обработке изображений часто возникает задача анализа бинарных изображений, содержащих различные объекты. Одной из важных задач является нахождение компонент связности (связанных областей) и построение их выпуклых оболочек. Выпуклая оболочка представляет собой минимальный выпуклый многоугольник, содержащий все точки компоненты. Эта задача имеет широкое применение в компьютерном зрении, распознавании образов, обработке медицинских изображений и геометрических вычислениях.

Целью данной работы является разработка эффективного параллельного алгоритма для построения выпуклых оболочек компонент бинарного изображения с использованием технологии MPI, а также создание корректной последовательной версии для сравнения производительности.

## 2. Постановка задачи

**Формальная постановка задачи:**

Дано:
- Бинарное изображение размером W × H пикселей
- Каждый пиксель имеет значение 0 (фон) или 255 (объект)

Требуется:
1. Найти все связные компоненты (области из пикселей со значением 255)
2. Для каждой компоненты построить выпуклую оболочку
3. Вернуть список компонент с их выпуклыми оболочками

**Ограничения:**
- Используется 4-связность (пиксели связаны по горизонтали и вертикали)
- Изображение представляется в виде одномерного массива
- Загрузка реальных изображений не требуется (генерируются тестовые данные)

**Входные данные:**
```cpp
struct ImageData {
    int width;
    int height;
    std::vector<uint8_t> pixels; // 0 или 255
};
```

**Выходные данные:**
```cpp
struct Component {
    std::vector<Point> pixels; // Все точки компоненты
    std::vector<Point> hull;   // Выпуклая оболочка
};
```

## 3. Базовый алгоритм (последовательный)

Последовательный алгоритм состоит из двух основных этапов:

### 3.1 Поиск компонент связности (BFS)
```
Для каждого пикселя изображения:
    Если пиксель == 255 и не посещен:
        Запустить BFS/DFS для поиска всех связанных пикселей
        Сохранить найденные точки как отдельную компоненту
```

### 3.2 Построение выпуклой оболочки (Алгоритм Грэхема)
```
Для каждой компоненты:
    Если точек ≤ 2: оболочка = точки
    Иначе:
        1. Найти нижнюю-левую точку (опорную)
        2. Отсортировать остальные точки по полярному углу
        3. Построить оболочку, удаляя невыпуклые вершины
```

**Псевдокод алгоритма Грэхема:**
```
GrahamScan(points):
    pivot = точка с минимальной Y (и минимальной X при равенстве)
    sort(points по углу относительно pivot)
    hull = empty stack
    for p in sorted_points:
        while len(hull) ≥ 2 and cross(hull[-2], hull[-1], p) ≤ 0:
            hull.pop()
        hull.push(p)
    return hull
```

**Сложность:**
- Поиск компонент: O(W×H)
- Построение оболочки: O(n log n) для n точек в компоненте
- Общая сложность: O(W×H + N⋅n log n), где N - количество компонент

## 4. Схема распараллеливания (MPI)

### 4.1 Архитектура параллельного алгоритма

```
    ┌─────────────────────────────────────────┐
    │           Процесс 0 (Master)            │
    │ Чтение → Разделение → Слияние → Рассылка│
    └─────────────────┬───────────────────────┘
                      ↓
          ┌───────────┼──────────┐
          ↓           ↓          ↓
    ┌─────────┐ ┌─────────┐ ┌─────────┐
    │Процесс 1│ │Процесс 2│ │Процесс N│
    └─────────┘ └─────────┘ └─────────┘
```

### 4.2 Распределение данных

Изображение делится горизонтальными полосами между процессами:
```cpp
int rows_per_proc = height / num_procs;
int remainder = height % num_procs;
// Каждый процесс получает rows_per_proc + (если остаток) строк
```

### 4.3 Этапы параллельного алгоритма

1. **Распределение данных** (`MPI_Scatterv`)
   - Процесс 0 делит изображение и рассылает части

2. **Локальный поиск компонент** (параллельно)
   - Каждый процесс находит компоненты в своей полосе

3. **Сбор фрагментов** (`MPI_Gather` + `MPI_Send/Recv`)
   - Все процессы отправляют компоненты процессу 0

4. **Слияние фрагментов** (только процесс 0)
   - Объединение компонент, разделенных границами полос
   - Используется Union-Find (DSU) с хэш-таблицей

5. **Построение оболочек** (только процесс 0)
   - Для каждой объединенной компоненты строится оболочка

6. **Рассылка результата** (`MPI_Bcast`)
   - Все процессы получают финальный результат

### 4.4 Обработка граничных случаев

Компоненты, пересекающие границы полос, обнаруживаются с помощью проверки 8-соседей:
```cpp
for точка in компонента:
    for сосед in 8_соседей(точка):
        if сосед принадлежит другой компоненте:
            объединить_компоненты(текущая, соседняя)
```

### 7.2 Производительность

**Результаты тестов производительности (изображение 4096×4096):**

| Технология | Процессы | Режим      | Время (сек) | Ускорение | Эффективность |
|------------|----------|------------|-------------|-----------|---------------|
| SEQ        | 1        | task_run   | 0.0449      | 1.00      | 100%          |
| MPI        | 1        | task_run   | 0.1278      | 0.35      | 35%           |
| MPI        | 4        | task_run   | 0.1331      | 0.34      | 8.5%          |
| MPI        | 8        | task_run   | 0.1371      | 0.33      | 4.1%          |

**Анализ результатов:**

1. **Неожиданные результаты**: MPI версия показала значительно худшую производительность по сравнению с SEQ версией даже при использовании одного процесса.

2. **Основные причины низкой производительности MPI:**
   - **Накладные расходы MPI**: Инициализация MPI, создание коммуникаторов и управление процессами добавляют значительные накладные расходы.
   - **Централизованная архитектура**: Все данные собираются на процессе 0, который становится узким местом.
   - **Избыточная коммуникация**: Алгоритм использует множественные вызовы `MPI_Gatherv`, `MPI_Bcast` и `MPI_Send/Recv`.
   - **Плохая масштабируемость**: Время выполнения увеличивается с ростом числа процессов из-за увеличения накладных расходов на коммуникацию.

3. **Сравнение с теоретическими ожиданиями**:
   - Ожидалось ускорение 2-4× при 4-8 процессах
   - Фактически получили замедление в 2.8-3.0 раза
   - Это указывает на фундаментальные проблемы в архитектуре алгоритма

### 7.3 Анализ узких мест

**Профилирование выявило следующие проблемы:**

1. **`GatherAllFragments()`**: Занимает до 40% времени выполнения в MPI версии
   - Множественные вызовы коллективных операций
   - Неэффективная упаковка/распаковка данных
   - Избыточная передача метаданных

2. **`MergeFragmentsOnRank0()`**: Занимает до 30% времени
   - O(n²) сложность для проверки соседей
   - Неэффективное использование хэш-таблиц
   - Последовательная обработка на одном процессе

3. **`BroadcastFinalResult()`**: Занимает до 20% времени
   - Рассылка всех данных всем процессам, даже если они не нужны
   - Избыточная сериализация структур данных

### 7.4 Сравнение с идеальным распараллеливанием

**Теоретический анализ:**
- Общее количество операций: ~100 миллионов
- Ожидаемое время при идеальном распараллеливании на 8 ядрах: ~0.0056 секунд
- Фактическое время: 0.1371 секунд
- **Эффективность: ~4.1%** (крайне низкая)

### Исправленная функция `GatherAllFragments()`
```cpp
void VidermanAConvexHullMPI::GatherAllFragments() {
    // 1. Упаковываем все точки в один массив с метаданными
    struct LocalData {
        int comp_count;
        std::vector<int> comp_sizes;
        std::vector<Point> points;
    };
    
    LocalData local;
    local.comp_count = static_cast<int>(local_components_.size());
    
    for (const auto& comp : local_components_) {
        local.comp_sizes.push_back(static_cast<int>(comp.pixels.size()));
        local.points.insert(local.points.end(), comp.pixels.begin(), comp.pixels.end());
    }
    
    // 2. Собираем количество компонент
    std::vector<int> comp_counts(size_);
    MPI_Gather(&local.comp_count, 1, MPI_INT,
               comp_counts.data(), 1, MPI_INT,
               0, MPI_COMM_WORLD);
    
    // 3. Собираем размеры компонент
    std::vector<int> all_comp_sizes;
    if (rank_ == 0) {
        int total_comps = std::accumulate(comp_counts.begin(), comp_counts.end(), 0);
        all_comp_sizes.resize(total_comps);
    }
    
    // Подготавливаем смещения
    std::vector<int> displs_size(size_, 0);
    std::vector<int> recvcounts_size(size_);
    if (rank_ == 0) {
        for (int i = 1; i < size_; ++i) {
            displs_size[i] = displs_size[i - 1] + comp_counts[i - 1];
        }
        for (int i = 0; i < size_; ++i) {
            recvcounts_size[i] = comp_counts[i];
        }
    }
    
    MPI_Gatherv(local.comp_sizes.data(), local.comp_count, MPI_INT,
                rank_ == 0 ? all_comp_sizes.data() : nullptr,
                recvcounts_size.data(), displs_size.data(), MPI_INT,
                0, MPI_COMM_WORLD);
    
    // 4. Собираем точки
    int local_point_count = static_cast<int>(local.points.size());
    std::vector<int> point_counts(size_);
    MPI_Gather(&local_point_count, 1, MPI_INT,
               point_counts.data(), 1, MPI_INT,
               0, MPI_COMM_WORLD);
    
    std::vector<int> all_points;
    if (rank_ == 0) {
        int total_points = std::accumulate(point_counts.begin(), point_counts.end(), 0) * 2;
        all_points.resize(total_points);
    }
    
    // Упаковываем точки в плоский массив
    std::vector<int> flat_points(local_point_count * 2);
    for (size_t i = 0; i < local.points.size(); ++i) {
        flat_points[i * 2] = local.points[i].first;
        flat_points[i * 2 + 1] = local.points[i].second;
    }
    
    std::vector<int> displs_points(size_, 0);
    std::vector<int> recvcounts_points(size_);
    if (rank_ == 0) {
        for (int i = 1; i < size_; ++i) {
            displs_points[i] = displs_points[i - 1] + point_counts[i - 1] * 2;
        }
        for (int i = 0; i < size_; ++i) {
            recvcounts_points[i] = point_counts[i] * 2;
        }
    }
    
    MPI_Gatherv(flat_points.data(), local_point_count * 2, MPI_INT,
                rank_ == 0 ? all_points.data() : nullptr,
                recvcounts_points.data(), displs_points.data(), MPI_INT,
                0, MPI_COMM_WORLD);
    
    // 5. Восстанавливаем компоненты на процессе 0
    if (rank_ == 0) {
        all_fragments_.clear();
        int point_offset = 0;
        int comp_offset = 0;
        
        for (int proc = 0; proc < size_; ++proc) {
            for (int c = 0; c < comp_counts[proc]; ++c) {
                Component comp;
                int comp_size = all_comp_sizes[comp_offset++];
                comp.pixels.resize(comp_size);
                
                for (int p = 0; p < comp_size; ++p) {
                    comp.pixels[p] = {
                        all_points[point_offset],
                        all_points[point_offset + 1]
                    };
                    point_offset += 2;
                }
                
                all_fragments_.push_back(comp);
            }
        }
    }
}
```

void VidermanAConvexHullMPI::BroadcastFinalResult() {
    OutType &output = GetOutput();
    
    // 1. Все процессы получают количество компонент
    int total_components = 0;
    if (rank_ == 0) {
        total_components = static_cast<int>(output.size());
    }
    
    MPI_Bcast(&total_components, 1, MPI_INT, 0, MPI_COMM_WORLD);
    
    if (total_components == 0) {
        if (rank_ != 0) {
            output.clear();
        }
        return;
    }
    
    // 2. На процессе 0 готовим данные для рассылки
    std::vector<int> component_sizes(total_components * 2); // [pixels_count, hull_count]
    std::vector<int> displacements(total_components + 1, 0);
    std::vector<int> all_data;
    
    if (rank_ == 0) {
        // Вычисляем общий размер данных
        int total_data_size = 0;
        for (int i = 0; i < total_components; ++i) {
            component_sizes[i * 2] = static_cast<int>(output[i].pixels.size());
            component_sizes[i * 2 + 1] = static_cast<int>(output[i].hull.size());
            displacements[i + 1] = displacements[i] + 
                                   component_sizes[i * 2] * 2 +  // точки
                                   component_sizes[i * 2 + 1] * 2; // оболочка
            total_data_size = displacements[i + 1];
        }
        
        // Собираем все данные в один буфер
        all_data.resize(total_data_size);
        int offset = 0;
        for (int i = 0; i < total_components; ++i) {
            // Точки компоненты
            for (const auto& point : output[i].pixels) {
                all_data[offset++] = point.first;
                all_data[offset++] = point.second;
            }
            // Точки оболочки
            for (const auto& point : output[i].hull) {
                all_data[offset++] = point.first;
                all_data[offset++] = point.second;
            }
        }
    }
    
    // 3. Рассылаем размеры компонент всем процессам
    MPI_Bcast(component_sizes.data(), total_components * 2, MPI_INT, 0, MPI_COMM_WORLD);
    
    // 4. Рассылаем смещения
    MPI_Bcast(displacements.data(), total_components + 1, MPI_INT, 0, MPI_COMM_WORLD);
    
    // 5. Рассылаем все данные
    int total_data_size = 0;
    if (rank_ == 0) {
        total_data_size = displacements[total_components];
    }
    MPI_Bcast(&total_data_size, 1, MPI_INT, 0, MPI_COMM_WORLD);
    
    if (rank_ != 0) {
        all_data.resize(total_data_size);
    }
    
    MPI_Bcast(all_data.data(), total_data_size, MPI_INT, 0, MPI_COMM_WORLD);
    
    // 6. Восстанавливаем компоненты на всех процессах (кроме 0)
    if (rank_ != 0) {
        output.clear();
        output.reserve(total_components);
        
        int data_offset = 0;
        for (int i = 0; i < total_components; ++i) {
            Component comp;
            
            // Восстанавливаем точки компоненты
            int num_pixels = component_sizes[i * 2];
            comp.pixels.resize(num_pixels);
            for (int p = 0; p < num_pixels; ++p) {
                comp.pixels[p] = {all_data[data_offset], all_data[data_offset + 1]};
                data_offset += 2;
            }
            
            // Восстанавливаем оболочку
            int num_hull = component_sizes[i * 2 + 1];
            comp.hull.resize(num_hull);
            for (int h = 0; h < num_hull; ++h) {
                comp.hull[h] = {all_data[data_offset], all_data[data_offset + 1]};
                data_offset += 2;
            }
            
            output.push_back(comp);
        }
    }
}
